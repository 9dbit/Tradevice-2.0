# Basket TP by points — 16 October 2026

Adds `Points · price distance` to Batch settings. Input is a whole number from 1 to 100,000 points. Existing fixed $3.50, custom USD, and current ATR USD modes retain their meaning and payloads.

For the verified XAUUSDm contract, point = 0.001. A 4,200-point target is a 4.200 price distance above the basket volume-weighted entry for BUY, below it for SELL. The distance is fixed for the cycle; the basket average and common TP price update after actual fills. BUY uses executable bid, SELL uses ask. Broker tick rounding remains outward. Gross USD equivalent scales with total volume; commissions, swap and execution affect realized net profit. This is not a promise of a fixed USD result or profitability.

The additive `POINTS` mode uses `tpPoints` and requires `customTpUsd=null`. Other modes reject the extra field, preserving old journal configuration proofs exactly. Old API/bridge versions reject the unfamiliar payload before dispatch rather than silently treating it as USD. Settings matching includes the points amount, so evidence for 1,000 points cannot verify 4,200. The existing protocol identifier remains unchanged because the four old modes retain exact semantics; new mode support requires this reviewed API and engine update.

Engine configuration registers `POINTS_PRICE_DISTANCE` and a proof-bound distance; existing distance-aware pending TP, live coordinator and broker-history reconciliation paths are reused. No fixed USD exit is applied to this mode. Historical journal completion still requires owned complete exit volume, TP price/reason evidence and broker-flat cleanup; manual exits cannot masquerade as TP completion. Hard loss stays −$250 for Points, with existing margin, identity, news, ATR/ADX entry and reconciliation guards. No new trading authorization is granted.
